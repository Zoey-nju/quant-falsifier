# Security policy

## Supported versions

The latest released minor version receives security fixes. Older versions are not patched;
the library has no long-term support branch.

| Version | Supported |
| --- | --- |
| 0.1.x | Yes |
| < 0.1 | No |

## Reporting a vulnerability

Please **do not open a public issue**. Use GitHub's private vulnerability reporting:

1. Go to the repository's **Security** tab.
2. Choose **Report a vulnerability**.
3. Describe the issue, the affected version, and a minimal reproduction if you have one.

If private reporting is unavailable, open a public issue titled "security contact requested"
and wait for a private channel; do not include exploit details in the issue. You can expect an
acknowledgement within a few days and an assessment within two weeks. Please give us a
reasonable window to ship a fix before disclosing publicly.

## What counts as a vulnerability here

This library performs numerical analysis on user-supplied arrays. The relevant classes of
issue are:

- **Arbitrary code execution** through deserialisation, for example a crafted ledger file
  that is executed rather than parsed. Ledgers are read as JSON Lines with `json.loads` and
  never unpickled; report any place that changes this.
- **Unexpected filesystem access.** The CLI only writes inside the `--out` directory it is
  given. A path traversal that escapes that directory is a vulnerability.
- **Denial of service** through unbounded memory allocation, for example a bootstrap request
  that materialises an array far larger than the number of observations implies.
- **Integrity failures in `TrialLedger`.** If a tampered ledger can pass `verify()`, or if two
  distinct records can produce the same hash, that defeats the purpose of the module.

Ordinary statistical inaccuracy is a correctness bug, not a vulnerability. Report those as
normal issues with a reference to the paper.

## Sensitive data in this project

The repository intentionally contains **no market data and no credentials**. Tests and the
demo use seeded synthetic series generated by `quant_falsifier.synthetic`. If you find a real
dataset, broker export, access token or key committed anywhere in this repository, treat it
as a security issue and report it privately.

Never put credentials in a ledger file, a report, or an issue. `TrialLedger` records
parameters verbatim and hashes them; it does not redact anything.
